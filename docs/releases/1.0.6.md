# HotbarPets 1.0.6 — default Slimefun permission namespace (UNRELEASED)

This is a **new, unpublished** Java addon maintenance candidate. The official [v1.0.5](https://github.com/wickidcow/SF_HotbarPets/releases/tag/v1.0.5) and the canonical Slimefun Legacy 4.1.78/r153 release remain unchanged.

## Requested default namespace

- New installations use `permission-gating.prefix: 'slimefun.hotbarpet.'`.
- The resulting Pig Pet node is `slimefun.hotbarpet.pig`. Enderman is `slimefun.hotbarpet.ender_man`; Cookie Slime is `slimefun.hotbarpet.mrcookieslime`.
- `permission-gating.enabled: false` **remains the packaged default**. Pet crafting, research, ownership, food types, item IDs, interaction effects and existing saves do not change.
- **Existing servers keep their saved config**, so Albion's present `prefix: 'albion.hotbarpet.'` stays active unless an operator intentionally edits it. Legacy `albion.hotbarpet.*` permissions remain available by configuring that exact prefix.
- The plugin checks the configured prefix **only**, not both. If migrating to the new default, update the Albion NPC/LuckPerms grants or the affected players' effective permissions.
- If a non-OP player can use a gifted pet with gating active and no apparent node, inspect their effective permissions and inherited group/wildcard grants before alleging a permission bypass.

## Validation / release boundary

This candidate is separate from the immutable published v1.0.5 JAR. CI must pass 52 tests with zero failures/errors/skips, three supported Paper API compile targets, reproducible Java 21 bytecode, and stable Paper 26.2/26.3 two-boot startup checks with the published Slimefun Legacy v4.1.78 core. Purpur/Leaf/Folia startup checks remain advisory, not actual player gameplay certification. Manual `master` `workflow_dispatch` with `publish=true` and `confirm_version=1.0.6` is required for future release; merging does not publish automatically.

Never change previous release assets, Pylon, Rebar or Geyser/Bedrock functionality.
