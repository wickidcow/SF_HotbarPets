# HotbarPets 1.0.5 — Java maintenance and release acceptance notes

This document documents the reviewed changes in [PR #7](https://github.com/wickidcow/SF_HotbarPets/pull/7). A GitHub Release is authoritative for publication status; an Actions artifact is not a release. Official v1.0.4 remains immutable and pinned in Slimefun Legacy 4.1.78/r153. Never overwrite or republish those files.

## Candidate behavior corrections

- Register the missing Pig/Zombie food-consumption Bukkit event listener. Avoid queued duplicate Pig or Zombie effects when the same pet occupies multiple hotbar slots; preserve their two different abilities.
- Keep Pig's delayed, entity-region-owned effect gated by execution-time permission and exactly one favorite-food debit, including offhand availability.
- Respect cancelled consumption/damage/phantom targeting events. Select Panda's actual proposed phantom target, not stale entity target state. Do not charge two defensive pets for one protected damage event.
- Avoid multiple Soul Pie drops from one kill when duplicated Eyamaz pets are equipped; evaluate Eyamaz eligibility from the killer's entity-owned Folia scheduler and return the drop to the death-location region, without cross-region inventory access or unpermissioned rewards. This intentionally defers the reward to the next tick.
- Allow a later Cookie Slime pet to protect from fall damage if an earlier Slime pet is hungry.
- Preserve Magma Cube's classic **30%** food-spend chance, but require food carried in storage or offhand and check the exact debit on paid activations.
- Preserve passive producer rewards when player storage is full by safely dropping only the uninserted remainder. Keep the original pet item/recipe identities and unchanged `production-interval-ticks: 2000` default.
- Make shared message cooldown accounting safe for multiple Folia player-region callbacks.
- Schedule Bed Pet's world daylight change on the Folia global-region scheduler, not the player's region, preserving its vanilla blindness effect and original food debit.
- Deliver Creeper/TNT denied-PvP feedback through the TNT owner's entity scheduler instead of accessing another region's player directly; retain the protection decision and damage-cancellation behavior.

## Source and compatibility constraints

- No new pet IDs, changes to favorite food item types, Slimefun research/recipes, permissions (still **OFF by default**), persisted records, resource pack, Pylon/Rebar or Bedrock/Geyser.
- Java 21 bytecode, with Paper 1.21.11 as baseline and 26.2/26.3 API compile targets. The independently maintained Slimefun Legacy **4.1.78** core remains published and unchanged.
- Before merging or publishing, require an exact-head green Maven suite with **zero skipped tests**, byte-identical clean JAR builds, the immutable published core hash, and **separate two-boot stable Paper 26.2 and 26.3** candidate checks. Both Paper versions must pass before the master-only explicit publication job can proceed.
- Advisory official **Folia 26.2 beta** two-boot addon-integration smoke runs on PRs using the immutable released Slimefun Legacy 4.1.78 JAR and the exact candidate JAR with a one-addon SHA-256 admission manifest. This verifies startup and registry evidence, never Folia player-region gameplay or a stable Folia certification.
- Advisory **Purpur 26.2** and **Leaf 26.2** two-boot addon startup checks use that same checksum-pinned 4.1.78 core, a single candidate-JAR digest admission manifest and Doctor diagnostics. They are independent PR-only jobs; green boot tests do not prove active pet abilities or grant/revoke behavior.
- A green startup/MockBukkit suite **does not replace non-OP gameplay acceptance**: staging must verify Pig/Zombie/Panda/Magma Cube, duplicate pet items, offhand payment, food depletion, per-pet LuckPerms/Albion NPC grants and revocation, full-inventory producer rewards, cancelled events and restart data. Purpur/Leaf/Folia multi-region player behavior needs separate review.

## Publication boundary

The new canonical standalone asset name is `SF_HotbarPets1.0.5.jar`. The release workflow must be explicitly dispatched with `publish=true`, `confirm_version=1.0.5`, on **master** only; it requires that master has not advanced and that same-run build plus native smoke succeeded. It refuses an already-existing release/tag. Operator-reported staging: two Pig Pets with carrots in the offhand consumed exactly one carrot per bread eaten, the hungry-pet warning appeared when food was absent, and the Pig food-protection behavior worked. Other pets and non-OP permission-grant/revoke and Folia multi-region interaction remain untested by live players; do not claim complete certification. The operator explicitly authorized a new standalone 1.0.5 release on this reviewed PR. Publication is guarded as a one-time push of PR #7 into master from the exact premerge source, requiring PR CI plus same-run Paper 26.2 and 26.3 startup checks and the passing 50-test gate. For all later releases, manual master dispatch is still required. The existing v1.0.4 release and Slimefun Legacy 4.1.78/r153 ZIP are immutable.
